# ADR-009 — Internationalization depth

**Status:** Approved 2026-08-30. Depends on ADR-008. Details in `02-architecture/06-i18n.md`.

## Context

Default UI language English; Russian and Ukrainian switchable from day one; every
language eventually. Content (species, spells, items, homebrew) must be translatable but
optionally — untranslated fields fall back to English. Russian and Ukrainian have three
plural forms (one/few/many + other) and grammatical gender that leaks into sentences
about the character ("she took damage"). Search and sorting must work in Cyrillic.
Research (2026-08-29): no reusable Russian or Ukrainian translation of SRD 5.2 exists;
the only open Russian SRD translation is 5.1 under CC-BY-**SA** (share-alike). Owner
decision: content ships in English only for now; translate a sample to prove the pipeline.

## Options considered

### UI strings

| Option | Assessment |
|--------|-----------|
| `@angular/localize` | Compile-time: one build per locale, language switch = reload, no runtime loading of community translations. Rejected. |
| ngx-translate 18 | Healthy; ICU needs a third-party compiler. |
| **Transloco 8 + `@jsverse/transloco-messageformat` (chosen)** | Runtime switching, lazy scopes per feature, first-party ICU (plural/select), keys manager for extraction. Pin 8.x (v9 is alpha). |

### Content translations

| Option | Assessment |
|--------|-----------|
| Inline `i18n` map inside each entity | Translators must edit the source pack; versions entangle. |
| **Separate translation packs (chosen)** | `kind: translation`, `locale: "ru"`, `translates: "srd-5e-2024"`, `range: "^1"`; strings keyed by entity id and field path. Community can ship translations independently; several can coexist; fallback is per field. |

## Decision

### Source of truth

**English** is the source language for both UI and content (SRD is English). Every other
language is a translation with per-key fallback to English. The UI never shows a key.

### UI

- Transloco with JSON files per scope: `assets/i18n/<scope>/<locale>.json`; scopes match
  feature folders (`characters`, `campaigns`, `library`, `sheet`, `common`).
- Key convention: `scope.component.meaning` (`sheet.hp.take-damage`). No sentence
  concatenation; every sentence is one key with ICU placeholders.
- ICU everywhere a number or gender appears: `{count, plural, one {…} few {…} many {…}
  other {…}}`; `{gender, select, feminine {Она} masculine {Он} other {Оно}}`.
- **Grammatical gender** is a character field (`grammaticalGender: masculine | feminine |
  neuter`, default from nothing — asked at creation as "How should text refer to your
  character?"). It is passed to every UI string that mentions the character. It is about
  text, not identity, and the label says so.
- Locale switching at runtime without reload; the choice persists per device; the initial
  guess is `navigator.languages` ∩ supported.
- Formatting through `Intl`: numbers, dates, lists (`Intl.ListFormat`), relative time.
- Lint rule: no string literals in templates (`@angular-eslint/template/i18n` configured
  for Transloco attributes) — this is what makes "structural from commit one" enforceable.

### Content

- Engine `Localizer.text(entityId, fieldPath, locale)` resolves: translation pack for
  `locale` → translation pack for the base language of `locale` (e.g. `ru` for `ru-UA`)
  → the entity's English field. The result carries `isFallback` so the UI can mark
  untranslated text subtly (italic marker in the library only, never on the sheet).
- Translatable fields are declared in the entity schema (name, description, feature names
  and texts, item flavor, choice prompts). Numbers, formulas, ids are never translated.
- Homebrew packs may embed translations for their own entities directly (`i18n` map)
  because a solo author will not maintain two files; the pack build tool splits them into
  a translation pack on export if asked. Both are read by the same Localizer.
- Terminology glossary (`04-reference/glossary.md` will gain RU/UK columns): follow the
  de-facto community conventions — dnd.su for Russian, 5esrd.kyiv.ua for Ukrainian —
  for *terms* (ability names, conditions, schools). Terms are not copyrightable text;
  their translated descriptions are, and are not copied.

### Search and collation

- A per-locale search index over entity `name`, `aliases`, and English `name` (so
  "fireball" finds "Огненный шар" and vice versa). Normalization: lowercase, NFD +
  strip combining marks, `ё → е`, `’ → '`; prefix and substring match; simple ranking
  (exact > prefix > substring; name > alias).
- Sorting with `Intl.Collator(locale, {sensitivity: "base", numeric: true})`; never
  `localeCompare` without a locale.

### Right-to-left

Not needed now; CSS uses logical properties (`margin-inline-start`) and `dir` is set from
the locale so RTL languages are not precluded.

## Consequences

- Phase 1 ships EN UI strings complete, RU/UK UI strings complete (they are small), and a
  demo translation pack `srd-5e-2024-ru-sample` covering a handful of entities to exercise
  fallback, search and rendering.
- Translation contributions are files, not code; a later "suggest a fix" feature exports a
  patch file.
- The CC-BY-SA Russian 5.1 translation is not used (share-alike would constrain our RU
  text); if a 5.2 translation is ever adopted, its license must be CC-BY or more
  permissive, and the attribution screen must list it.

## Open points

- Which Ukrainian source to align terminology with if 5esrd.kyiv.ua's licensing stays
  unclear; alignment of *terms* does not require a license, so this only affects text.
