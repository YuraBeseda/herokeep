# Internationalization implementation

Decision record: ADR-009. This document is the how.

## Locales

`en` (source), `ru`, `uk` from day one. Locale ids are BCP-47; matching uses
`Intl.LocaleMatcher`-style best fit (`ru-UA` → `ru`). Adding a locale = adding UI JSON
files and, optionally, translation packs; no code.

## UI strings (Transloco 8 + messageformat)

- Files: `apps/web/src/assets/i18n/<scope>/<locale>.json`; scopes: `common`, `auth`,
  `characters`, `sheet`, `campaigns`, `library`, `packs`, `settings`, `timeline`.
  Scopes are lazy-loaded with their feature routes.
- Provider setup: `provideTransloco({ config: { availableLangs, defaultLang: 'en',
  fallbackLang: 'en', reRenderOnLangChange: true, missingHandler: { useFallbackTranslation:
  true } }, loader })` plus `provideTranslocoMessageformat({ locales: ['en','ru','uk'] })`.
- Templates use the structural directive (`*transloco="let t; read: 'sheet'"`) or the
  pipe; TS code uses `TranslocoService.translate` only in services that produce user text
  (timeline sentences, notices).
- Keys: `scope.area.meaning`, kebab-case, e.g. `sheet.hp.take-damage`,
  `timeline.event.hp-changed`. No dynamic key construction except the documented
  `timeline.event.<type>` family.
- ICU examples:
  - `"slots-remaining": "{count, plural, one {# slot left} other {# slots left}}"`
    (Russian file: `one {Остался # слот} few {Осталось # слота} many {Осталось # слотов}
    other {Осталось # слота}}`)
  - `"took-damage": "{name} {gender, select, feminine {получила} masculine {получил}
    other {получило}} {amount} урона"`
- Lint: `@angular-eslint/template/i18n` with `checkText`, `checkAttributes` for
  `title|placeholder|aria-label|alt`, ignoring Transloco-bound attributes; CI fails on
  literals. `transloco-keys-manager extract` runs in CI and fails on keys missing from
  `en`; missing `ru`/`uk` keys are reported, not failed (they fall back).

## Content text

- `Localizer` (engine) resolves per field with fallback and returns `{ text, locale,
  isFallback }`. Rendering: markdown → sanitized HTML via a small renderer (marked +
  DOMPurify equivalents chosen in Phase 1a; must run in a Web Worker-free main thread
  quickly), with a custom link resolver for `[[entity-id]]` cross-references.
- The Library shows fallback text with a subtle "EN" tag; the sheet never tags.

## Grammatical gender

`Facts.grammaticalGender ∈ {masculine, feminine, neuter}`; the creation wizard asks
"How should text refer to your character?" with examples in the current locale; default
is chosen by the user, never inferred. Every timeline/notice string that mentions the
character receives `gender`. Strings about the *user* ("you") avoid gendered forms in
ru/uk by phrasing (imperative/neutral constructions), a rule written in the translators'
guide.

## Pluralization and formatting helpers

- `Intl.PluralRules(locale)` is used by messageformat; direct calls only in the search
  results summary.
- `Intl.NumberFormat` for weights/currency; `Intl.RelativeTimeFormat` for "2 hours ago";
  `Intl.DateTimeFormat` for session dates; `Intl.ListFormat` for "STR, DEX and CON".
- Measurement units stay imperial as in the SRD (feet, pounds) with a per-user display
  toggle to metric (5 ft = 1.5 m, 1 lb = 0.45 kg) — display only; rules use feet.

## Search and sort

- Normalization: NFD → strip `\p{M}` → lowercase → `ё→е`, `’→'`, collapse whitespace.
  Ukrainian `і/ї/є/ґ` are preserved (they are distinct letters), but a secondary index
  of `і→и` transliteration improves tolerant matching; ranking prefers exact.
- Index built per (content index, locale) and cached; ~1,200 SRD entities index in
  < 30 ms.
- Lists sort with `Intl.Collator(locale, { sensitivity: 'base', numeric: true })`.

## Translators' workflow (Phase 5 and community)

1. Run `pack-tools i18n extract <pack> --locale ru` → skeleton translation pack with
   English text as comments.
2. Translate; run `pack-tools validate`.
3. Import the translation pack in Settings → Language → Content translations (solo) or
   enable it in the campaign (DM); fallback keeps everything else in English.

## Testing

- Unit tests render ICU strings for `en/ru/uk` with counts 1, 2, 5, 21 and all three
  genders.
- A snapshot test lists untranslated UI keys per locale (allowed to be non-empty for
  content, not for UI).
- Golden search tests: "fireball", "огненный", "огненн", "шар", "fire ball" → the same
  entity.
